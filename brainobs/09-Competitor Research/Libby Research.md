# Libby Research

The library app by OverDrive. Included because its language and framing are the best example in
the entire research set of a reading app that sells calm, warmth, and personal control rather than
engagement mechanics.

Evidence: official product page, evidence quality **strong** for described features.

Source: `https://www.overdrive.com/apps/libby`

## Positioning language

The page opens with:

```text
"Your guide to reading happiness."
"Warm, personal, and easy to use, Libby is great for users of all ages."
```

Then, notably, it uses reader quotes as the primary social proof rather than feature bullets.

This is the same positioning Bookflow already targets, which validates that the calm-reader
strategy is a real market position rather than a limitation.

## Feature inventory

### Access and borrowing

| Feature | Description |
| --- | --- |
| Library card sign-in | Borrow with an existing library card |
| Thousands of titles | Curated by the local library |
| Curated lists and catalog guides | Discovery through human curation |
| Holds with notifications | "Never miss a hold" |
| Send to Kindle | US libraries, hand off to a Kindle device |
| Kobo support | Read borrowed books directly on Kobo |

The hold-and-queue model is genuinely different from every other app researched: availability is
constrained by design, and the reader **waits**. Waiting is normally an anti-pattern, yet it
builds anticipation and perceived value.

### Reading experience

| Feature | Description |
| --- | --- |
| Font size adjustment | Accessible type control |
| Book layout adjustment | Measure and layout |
| Lighting adjustment | Comfort in the app |
| Bookmarks, notes, highlights | Full annotation |
| Article mode for magazines | Magazine-specific reading layout |
| Offline download or stream | Reader chooses storage versus bandwidth |

### Audio

| Feature | Description |
| --- | --- |
| Swipe cover to skip | Gesture-based audio navigation |
| Playback speed up to 3x | Fast listening |
| Sleep timer | End of chapter, or 5, 10, 30 minutes and more |
| Car integration | Apple CarPlay, Android Auto, Android Automotive, Bluetooth |

### To-be-read and tagging

"Tag it for later" creates a personal to-be-read list. This is one of the few features present
across essentially every app researched.

## Why readers describe it warmly

| Observed factor | Why it works |
| --- | --- |
| No engagement metrics | Nothing competes with reading |
| Waitlists create deliberate choice | Scarcity removes decision fatigue |
| Local library framing | The app is not the seller; it is the enabler |
| Reader quotes as marketing | Social proof from real usage, not fabricated urgency |
| Accessibility-first controls | Font, layout, and lighting are core, not buried |

## Lessons for Bookflow

| Lesson | Bookflow action |
| --- | --- |
| To-be-read list is universal | Adopt. Local, no account |
| Curation beats algorithmic volume | Adopt for the shelf: keep curated, add the reader's own books |
| Waitlist anticipation | Reject. Bookflow has no availability constraint, and fake scarcity is forbidden |
| Accessibility controls are not buried | Already aligned; keep settings prominent |
| Reader quotes as proof | Adopt for landing copy. Real quotes only, never invented |
| Warm, personal language | Adopt. Matches the existing landing voice |

The most transferable lesson is the framing: Libby never says "read more" or "build a streak". It
says "reading happiness". That is the register Bookflow already uses with "Read deeper. Keep going."

## Accessibility note

Font size, layout, and lighting adjustments are listed as core reading features on the main
marketing page, not hidden in a settings submenu. Bookflow already does this via the SettingsPanel,
and it is worth preserving prominently as the reader grows.
