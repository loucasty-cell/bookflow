# Build a companion for difficult passages

Reading Lens should help a reader get past a difficult passage and return to the PDF in the same place. The default reader stays quiet. A selection, a reader command, or an explicit choice to use the focused paragraph can open a compact assistant with the source passage visible. Offer a short explanation, a main point, and a question field, with translation and study tools one level deeper. The cartoon book wizard gives this tool a recognizable identity, while a restrained macOS-inspired panel keeps the text in charge. Make the request pipeline reliable before asking readers to trust the design. Every answer should retain the source it received, say where it was processed, and distinguish a completed response from an interrupted one. [Bookflow reader rules](../AGENTS.md#reader-experience-rules), [Human–AI interaction guidelines](https://doi.org/10.1145/3290605.3300233)

## Help should start at the reading impasse

The interaction starts with an explicit choice of text. A highlight exposes an Ask Lens action without opening a panel or making a request. Readers who cannot select a passage easily should have a keyboard-accessible **Use current paragraph** action that previews the actual paragraph before any send. Keep the excerpt stable while they scroll, change focus, or read a second passage. Show enough source text to recognize it and make truncation visible before submitting. A **Back to passage** action is useful when Bookflow knows the source anchor. Acrobat and Google's notebook product let readers jump from cited text to the document, although product documentation cannot establish improved comprehension. Bookflow should use page numbers only when the PDF import supplies them, and preserve the author’s page order. [Adobe Acrobat assistant](https://helpx.adobe.com/acrobat/desktop/use-acrobat-ai/generative-ai-features/ai-get-answers.html), [Google source and citation help](https://support.google.com/gemininotebook/answer/16179559?hl=en)

**Explain** should use common language, brief paragraphs, and the passage’s original terms where precision matters. **Main point** should answer in a few sentences. **Ask** should help an expert test an inference or a fiction reader resolve a reference within the selected excerpt. Translation belongs in a secondary menu with an explicit target language. A useful offline response would quote selected sentences verbatim and identify them as an excerpt. Broader explanation and translation depend on a remote model in the current architecture. A scanned PDF can supply usable reviewed OCR text, but when the passage is missing or garbled, the reader should get a short prompt to select readable text. The Lens needs neither the original image nor the entire PDF. [W3C cognitive accessibility guidance](https://www.w3.org/TR/coga-usable/#use-clear-and-understandable-content), [Bookflow grounding audit](<../research_notes/Bookflow reading companion/grounding-and-backend.md>)

For a later study mode, offer a single voluntary recall question and reveal the source sentence after the reader tries it. Educational prose experiments found better delayed retention with recall practice than with additional study, while additional study helped the immediate test. A separate high-school math experiment found performance differences between a general chat assistant and a guarded tutor. This supports testing a deliberate recall affordance. Bookflow-specific gains in retention or comprehension remain unmeasured. [Recall practice study](https://doi.org/10.1111/j.1467-9280.2006.01693.x), [Guarded tutor field experiment](https://doi.org/10.1073/pnas.2422633122)

## Keep the wizard in the window chrome

Use an original book-and-hat cartoon at header scale with a silhouette that reads in the collapsed control. The character can establish a distinct identity without an animated idle loop or a personality prompt in every answer. Keep the name **Reading Lens** visible and use plain text for processing, source, and consent state. Grok's official FAQ describes persona and tone options. That supports treating personality as a design choice while leaving the usefulness of this character to a Bookflow usability test. The mascot itself can be decorative for assistive technology when the nearby label already names the tool. [xAI consumer FAQ](https://x.ai/legal/faq), [Visual design research](<../research_notes/Bookflow reading companion/design.md>)

On desktop, use a small nonmodal window with a single translucent chrome layer, solid answer and composer surfaces, and Bookflow’s theme colors. Contrast needs to hold over a densely set page in both light and dark themes and when blur is unavailable. On narrow screens, favor a viewport-bounded sheet with its Close and composer controls in reach while the answer scrolls. At 320 CSS px and with text zoom, keep focused controls visible. If the card remains draggable, offer tap-to-dock positions and a reset alongside the keyboard controls. Escape should close the panel and return focus predictably. Announce short states such as “Reading the passage” and “Answer ready” separately from the streamed text. [Apple panels](https://developer.apple.com/design/human-interface-guidelines/panels), [Apple materials](https://developer.apple.com/design/human-interface-guidelines/materials), [Apple sheets](https://developer.apple.com/design/human-interface-guidelines/sheets), [WCAG dragging alternatives](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements), [WCAG reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow), [WCAG status messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages)

## An answer belongs to one captured passage

The pre-change audit found several failures that can undermine an otherwise polished panel. **Use current paragraph** read the current selection, explicitly attached text was compared against the live selection and could be discarded, and the floating tool could label a successful remote answer as offline. Save and regenerate could use current UI text instead of the answer’s source. A send-once grant could release several waiting submissions. Both the server and browser could interpret a stream that ended without confirmation as complete. The highest-value fix is to make one shared request path preserve these invariants across both reader surfaces. [Grounding and backend audit](<../research_notes/Bookflow reading companion/grounding-and-backend.md>)

Capture a **bounded passage, prompt, action, and target language** at submission. Bind the answer and its saved note to that snapshot. Show a source anchor when one exists and distinguish it from a claim the model made. The default cloud payload should contain the chosen passage and question. A one-time grant belongs to a single accepted submission, and a session grant needs clear wording and a way to revoke it. Keep provider keys on the server, reject missing and blank passages, and require explicit consent on the API side. Clear attached source and consent at the next book boundary. Ground content in the source and have the assistant say when the passage lacks enough evidence. Reserve separately authorized broader context for demonstrated reader needs. [Bookflow reader rules](../AGENTS.md#reader-experience-rules), [Grounding and backend audit](<../research_notes/Bookflow reading companion/grounding-and-backend.md>)

Let the reader stop a request. A late response from a cancelled or superseded request should leave the newer state alone. Treat unconfirmed EOF as interruption and a provider length cap as partial output. Keep already visible text clearly labeled as partial where useful, and keep it out of normal save or copy-ready flows until the reader can make an informed choice. Use a fallback provider only before any answer text is published. Retry must present or reuse the original scope, respect the current consent state, and require fresh permission when the prior grant was used up. [Gemini candidate finish reason](https://aistudio.google.com/api-reference/generate-content#Resource:Candidate), [Grounding and backend audit](<../research_notes/Bookflow reading companion/grounding-and-backend.md>)

## Convert every diagnosed failure into a check

Use the verification emphasis of Lauren Tan’s Code Summit talk as an engineering workflow for this change. Reproduce each important failure with a synthetic passage, add the narrow test that fails, fix the shared path, and rerun the same test before broad checks. A consent check should count actual outgoing requests and inspect their payloads. Cover **zero egress before consent**, one accepted remote request for a one-time grant, and no chapter attachment when only a paragraph was approved. Race tests should cover stale explicit versus implicit passage changes, pressing Stop, and old errors arriving after a newer request. Stream tests should cover normal termination, interrupted EOF after deltas, and fragments split at awkward boundaries. Where test cost is low, vary the same boundaries programmatically across many chunk splits. The talk is a process reference. This report makes no claim that Bookflow shares the speaker’s production scale or outcomes. [Lauren Tan, All Code Is Slop (Except Mine)](https://youtu.be/O_zcc6Xl12g), [Grounding and backend audit](<../research_notes/Bookflow reading companion/grounding-and-backend.md>)

Before expanding the assistant, test the reading loop end to end in a real browser with representative synthetic PDFs. Open the Lens, verify its source, get local or mocked remote assistance, close it, and find the same place in the document. Exercise the paths at desktop, 390 px, and 320 px with keyboard and touch, reduced motion, and fallback surfaces. Real mobile keyboards and screen readers need device checks. Provider integration, source fidelity, and the value of a recall feature are separate questions. Use a small public-domain benchmark with expected passages for provider evaluation and observe how quickly people return to the right sentence in a usability session. [Bookflow verification requirements](../AGENTS.md#required-verification-pipeline), [Reader needs research](<../research_notes/Bookflow reading companion/reader-needs.md>)

## Conclusion

The product measure that matters is whether a reader can resolve a question and resume at the same sentence with confidence in what the assistant used. Judge new capabilities against that reading loop. Page-anchored evidence and a clear way back to the text deserve priority over a larger chat surface or more personality options.
